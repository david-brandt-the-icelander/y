# E4 and E5: agents in Rust and in bare Rust

Proposal [`bare-rust.md`](../../../proposal/bare-rust.md) § 10.

- **E4:** 20 tasks × 2 arms (Rust; bare Rust with the JSON and the library file) × 2 trials, 80 runs.
- **E5:** 10 of those tasks × 2 variants of the bare arm (no library file; the library file with every `unexpressed`
  clause removed) × 2 trials, 40 runs. The full-library variant is E4's bare arm on the same tasks.

Every agent was Claude Sonnet 5.5 at the default effort, started fresh with one short prompt that pointed at the
workspace's `TASK.md`. The full tables are in [`e4-e5-tables.md`](e4-e5-tables.md), the output of
`experiments/summarize.py`. Each run's graded record is in `experiments/results/<run_id>.json`.

**Reproduce.** The harness is in [`experiments/`](../experiments/README.md):

- `prepare.sh <task> <arm> <trial> <dir>` builds a workspace.
- An agent works in that workspace.
- `record.py <run_id> <dir> --agent-file <dir>/RESULT.json …` grades the run and stores the result.
- `summarize.py` prints the tables.

## The tasks

There are 20 tasks, taken from strsim and fnv. They have three properties:

- **Each one starts from today's crate,** with one upstream behaviour or feature removed. Each has hidden tests,
  which the starting point fails and the upstream reference passes.
- **12 change bodies only and 8 change signatures.** Every signature task adds a public item or a trait impl. None
  changes the signature of an existing item.
- **10 are E5 tasks,** chosen because they touch `std` behaviour the library file describes: `chars`, `HashMap`,
  hashing and iterators.

`experiments/tasks/` holds every statement, starting snapshot and reference solution, and `verify_tasks.sh` checks
them all.

### What a pass means

The grader takes the agent's files and weaves them where the bare arm needs it. It then compiles the crate and runs
the hidden tests.

The agent's self-report agreed with the grader in all 120 runs. 15 runs wrote no `RESULT.json`. For those, the JSON
line from the agent's final message was recorded instead.

## Reading

- **Every run passed, so E4 cannot rank the arms by success.** The tasks are each a few lines in a single-file crate,
  and Sonnet solves them all in either form. The proof of concept chose this size (§ 14.2) to give a clear signal at
  low cost. On pass rate it gave none: the bare form costs no correctness on these tasks, and that is all it shows.
  Measuring a difference in success needs harder tasks: several files, changes to existing signatures, and history
  further back.
- **On body tasks the bare arm costs the same.** It took 1.2 attempts and 216K tokens against 1.2 and 222K. The
  bodies an agent edits are shorter, at 2.3 lines changed against 4.9, because the signatures are not in them. This
  is the case language § 11.2 rests on, and it holds.
- **On signature tasks the bare arm costs about twice the attempts and half as many tokens again.** It took 2.1
  attempts and 349K tokens against 1.1 and 226K.
  - Every extra attempt has the same cause: the agent had to learn how an item is split. It does not see the split
    anywhere it could copy it:
    - `let x: T` is a parse error in a bare body (at least 10 runs reported it);
    - a type alias is a body-less `type X;` with a `kind: alias` entry (all 6 bare runs of `fnv-aliases`, the costliest, at 3 to 8
      attempts);
    - an impl's entry names the trait as the source writes it.
  - None of these led to a wrong program, because the weaver refuses and names the slot that is missing. Each one
    cost a round trip.
  - The number of JSON edits matches what the task needs: 1.5 entries changed per signature task, all of them added
    entries.
- **The library file was not what the agents used.** Only 1 of the 80 bare-arm runs named a library promise it relied
  on (`std::fmt::Display::fmt`). Removing the file costs 0.4 attempts and 16% more tokens on the same tasks. Removing
  only its `unexpressed` clauses costs about half that. These differences are within the noise of 20 runs.
  - The tasks rarely turn on a promise of `std` that Sonnet does not already know.
  - So E5 at this size gives no reason to put closing the 52 `unexpressed` promises ([`language-gaps.md`](../../../proposal/language-gaps.md))
    ahead of other work.
  - It does not show that the file is worthless. It shows that the file's value lies in code an agent knows less
    well than `std`.
- **Bare extraction (open question 1) did not come up.** No agent touched an `.unwrap()` or `.expect()` on an input,
  so E4 gives no evidence either way.

## Changes the runs call for, all small

1. **A parse error for `let x: T` that names the fix.** It should say "types of locals go in `holes.locals`; or
   write a turbofish". Today the agent sees a raw tree-sitter error.
2. **Templates for new items.** For example, `bare-rust scaffold fn|impl|alias <name>`, which prints the bare stub
   and the JSON entry to fill in. Signature tasks spend their extra attempts on finding this shape.
3. **A short format reference in the workspace,** with one example of each kind of subject. `TASK.md` described the
   format in prose, and the agents worked it out from neighbouring entries.

|---|---:|---:|

| fnv-clone | 1.0 | 1.0 |
| fnv-const-hash | 1.5 | 2.5 |
| generic-hamming | 2.0 | 1.5 |

- **All 16 runs passed.**
- **Tokens per run were about the same:** 328K against 349K before.

**Reading.** The fixes removed the errors they were aimed at, but did not bring signature tasks down to the Rust arm's
cost.

- **No run hit the `let x: T` error.** The worst case before was 8 attempts, and the costliest runs are cheaper: the
  aliases took at most 4 attempts, and sorensen-dice 3 against 4.
- **The mean is unchanged, because the remaining attempts have other causes:**
  - **The cast hints for `as _`.** The weave reports such a hole as undetermined, and the agent adds a `holes` entry
    and weaves again. This happened in fnv-const-hash and ndl-add.
  - **Agents' own extra tests.** Each extra test the agent runs counts as an attempt.
  - **A bug in `scaffold`.** In fnv-aliases, it could not find `lib.brs` at the crate root (fnv's `[lib] path` is
    `lib.rs`), so the agent wrote the files by hand. The bug is now fixed, with a test.
- **Two trials per task is too few to read a change of 0.1 attempts.** The per-task differences are within the noise
  of the first run.

The next fix with a measurable effect is a better first answer for cast holes. The message could carry the hint
entry, as the missing-subject message already carries its entry. Alternatively, weave could accept a cast target
written in the body. That would be a change to the design (§ 2.2), so it is a question for the language, not the tool.

**Cost:** 16 runs, at an average of 328K input tokens (almost all cache reads), for about $1.5.

## Casts written as locals: a comparison

A cast in a bare body is `e as _`, with the target type in a positional hint. The alternative tried here moves the
cast out of the body at a binding: `let n = e;` with the local's entry `{"type": "f64", "cast": true}`, which weaves to
`let n: f64 = e as f64;`. Round trip still holds after `rustfmt` (proposal § 2), because the `cast` flag says where
the `as` goes back.

- **The tool.** `weave` always accepts the form. `strip --implicit-casts` (experimental, off by default) writes it for a
  cast that is the whole initialiser of a typed `let`, with a primitive target written as the local's type, and whose
  operand has exactly the brackets weave would put back. Everything else stays `as _` with a hint. Tests are in
  `tests/implicit_casts.rs`. E2's dropped-holes weave turns a dropped cast local into `let x: _ = e as _;`, so dropping
  a hole never drops the cast itself.
- **The arm.** `bare-castlocal` is the bare arm with the section of `FORMAT.md` on casts replaced by
  [`templates/format-castlocal.md`](../experiments/templates/format-castlocal.md), and one sentence in `TASK.md`. It
  tells the agent to name every new cast with a `let`, even where the Rust would cast mid-expression. Neither
  starting snapshot has a cast at a typed `let`, so both arms start from the same code.
- **The runs.** The two tasks whose reruns hit cast holes, 2 trials of each arm. Results are in
  `experiments/results/cast-*.json`.

| task | arm | passed | attempts | tokens per run |
|---|---|---:|---:|---:|
| fnv-const-hash | bare (`as _` and hints) | 2 of 2 | 2.5 | 358K |
| fnv-const-hash | bare-castlocal | 2 of 2 | 2.5 | 376K |
| ndl-add | bare (`as _` and hints) | 2 of 2 | 1.0 | 246K |
| ndl-add | bare-castlocal | 2 of 2 | 2.0 | 381K |
| **both** | **bare** | **4 of 4** | **1.75** | **302K** |
| **both** | **bare-castlocal** | **4 of 4** | **2.25** | **379K** |

**Reading.** The cast-local form is no cheaper for an agent, and on these runs it cost a little more.

- **Agents use it correctly.** All four castlocal runs wrote the form as documented: `let b = bytes[i]; hash ^= b;`,
  and `let dist = ...; let max_len = ...; 1.0 - dist / max_len`. Each `let` had a `cast: true` entry.
- **The `as _` arm did better than in the rerun above**, for reasons other than the form.
  - In ndl-add, both agents copied the neighbouring `normalized_levenshtein`, which already has the same two casts
    and their hints. Both passed on the first attempt.
  - In fnv-const-hash, both agents wrote `bytes[i] as u64`, with the target in the body. `weave` accepts a concrete
    cast target, since it is valid Rust, so no hint was needed. This form is not canonical: a strip of the woven
    code would give `as _` and a hint. But it cost the agent nothing.
- **The extra attempts in the castlocal arm** have other causes. One agent added `locals` entries for `hash` and `i`
  that bound to nothing. Another had a failed scripted insert. Neither is a cost of the form itself. The form saves
  nothing, because writing the `let` and its entry is the same work as writing the hint.
- **Too few runs to rank the arms.** Four runs per arm cannot tell 1.75 from 2.25. What they do show is that the
  form does not remove the cost it was meant to remove.
- **Strip would rarely use it.** With `--implicit-casts`, strip carries 0 of the 71 casts in strsim, fnv and the tool's own source. All of
  them are mid-expression (`(dist as f64) / (len as f64)`, `hash ^= byte as u64`) or have no typed `let`. So the
  form would only matter for new code that an agent chooses to write that way.

**What this suggests.** The cheap path agents found on their own is to write the cast's target in the body
(`as u64`), which weave already accepts. If that is allowed as an alternative bare spelling, cast hints become
optional for new code. Strip would still write `as _` and a hint for stripped code, unless the bare form keeps
primitive cast targets in the body. That is a question for the language: a primitive type in the body is a type
in the body, which § 2.2 keeps out. It is still the cheapest of the three forms tried.

**Cost:** 8 runs, an average of 340K input tokens, about $0.8.
