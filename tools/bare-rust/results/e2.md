# E2: bare in practice

Question 14 of the language, for one host (proposal § 10): weave every corpus with all `local` types and body hints dropped and only the signatures kept, and count the holes `rustc` cannot infer, per function and by kind. If few functions need a hint, bodies stay bare (principle 5); if many do, principle 5 must give, or the file must say more.

**Method.** Check 4 of `bare-rust check` does the weave: it strips the crate, removes every `holes.locals` and `holes.hints` entry from the constraint files, weaves, and runs `cargo check` (with `mut` derived). An inference error (E0282, E0283, E0284) at a hole site makes that hole *undetermined* ("not inferred"); an error that appears only because the hole was dropped, where `rustc` chose a type the program does not accept, is also counted ("inferred to a type the program rejects", found by restoring the function's dropped holes one at a time). No hole is ever filled by a guess (the "silently filled" row is 0 everywhere). `bare-rust e2` reads the `check.json` files that `check` wrote and prints the tables. "Functions" are the function subjects of the constraint files (methods, nested and test functions included). "Functions needing at least one hint" are the functions that have at least one undetermined hole.

**Reproduce.** From `tools/bare-rust`, after `corpora/fetch.sh` and `cargo build`:

```
bare-rust check corpora/src/strsim --check-only
bare-rust check corpora/src/fnv --check-only
bare-rust check tests/golden/crate --check-only --allow-missing-libraries
bare-rust check . --src-only --check-only --allow-missing-libraries
for e in examples/0*; do bare-rust check $e --check-only --allow-missing-libraries; done
W=target/bare-rust-check
bare-rust e2 $W/strsim $W/fnv $W/eve_cache $W/bare-rust
bare-rust e2 $W/lazy-buffer $W/intersperse $W/peeking-take-while $W/human-size $W/interpolate $W/sources
```

`--check-only` skips clippy and the tests (checks 1 to 4 run in full). `eve_cache` is the golden crate. The `bare-rust` column is the tool's own `src/` at the time of the run (27 files, 567 functions, including the modules written for stage 3); it grows with the tool, so rerun to refresh it. Toolchain: the stable `rustc` of the repository's CI; E0282-family messages differ between versions, the counts may too.

## Reading

- **Most holes need nothing.** Of 463 holes the strip step recorded (the type of a local, a cast target, a turbofish argument, a closure parameter, a literal suffix), `rustc` infers the right type for 336 from the signatures alone: 73 percent. The 127 it cannot are concentrated: locals 89 (a `let v = Vec::new()` or `.collect()` whose element type only the file knows), closure parameters 24 (all in the tool's own source, which uses closures over iterators heavily), casts 9, turbofish arguments 5, closure returns and literals 0.
- **Few functions need a hint.** 122 of 760 functions (16 percent) have at least one undetermined hole; 9 of 126 in strsim (7 percent), 1 of 10 in fnv, none of the 2 golden functions, 1 of 55 in the six examples (`interpolate::find_cap_ref`, a turbofish), and 111 of 567 (20 percent) in the tool's own source. The remaining 84 percent of functions are bare in the strong sense: signature and body together determine every type, and a reader of the `.brs` file sees all the program's types after reading the signatures only. Among the functions that do carry a hole (181), two thirds need a hint (67 percent), so a hole is not a rare accident in those functions; it is that most functions have none at all.
- **Rejected holes are the dangerous ones.** 18 holes are not "unknown to `rustc`" but "inferred wrongly": 9 are an unsized `[T]` chosen where the program means a `Vec<T>` (a `let v = x.collect()` or `.into()` whose target only the file states; E0277), 3 more are other unsatisfied trait bounds, 2 are type mismatches (E0308), and 4 are borrow errors that a closure parameter's type would have resolved (E0597, E0716, E0499). For these the weave fails loudly, which is what check 4 requires; no silent change of meaning was found (0 holes silently filled).
- **What it means for principle 5 and question 14.** For this host and these corpora the answer is that bodies stay bare: a hint is needed in about one function in six, and in one in fourteen for the two small library crates that the plan chose for their plain explicit signatures. The cost is not uniform: iterator-heavy code with `collect`, `parse`, `Default` and closures (the tool's own source) needs two to three times as many hints as arithmetic-and-loops code (strsim, fnv, the examples). The file therefore has to offer the hint slots, and the tool already does (`holes.locals`, `holes.hints`), but they can stay rare and local; there is no case for moving types back into bodies. Two caveats: the E2 count is of holes a *compiler* cannot determine, not of holes a *reader* finds hard to see; and the corpora are small (760 functions, one author style per crate), so a figure of 7 to 20 percent should be read as a range, not as a measurement of Rust at large.
